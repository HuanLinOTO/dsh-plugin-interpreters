# @huanlin/dsh-plugin-interpreters · dsh 0.1.2-alpha.1 → alpha.2 迁移指南

> 生成日期：2026-08-30 · 上游范围：tag `dsh-v0.1.2-alpha.1` (cd5ef81481) → `dsh-v0.1.2-alpha.2` (0a53fb55be)，234 commits / 1604 文件。
> 证据来源：插件源码全文精读 + 对 alpha2 tag 的只读 git 考查（`git -C D:/Projects/deepseek-harness/dsh show/diff/grep dsh-v0.1.2-alpha.2 ...`），未修改 dsh/ 任何文件。

## 结论

**⚠️ 需适配（一处小改，约 2 行）**：上游 alpha2 从 `@deepseek-ai/dsh-settings` 删除了 `settingsNamespace()` 导出，本插件 `src/settings.ts` 正在 import 它——不改则 **typecheck 与运行时 host 侧加载双双失败**（`lib/settings.js` 保留 ESM 具名导入，alpha2 包不再提供该具名导出）。改为裸字符串常量 `'interpreters' as const` 即完成迁移；其余全部 API 面（tools、webserver、client 槽位、connection/reset、模块表、peer semver）经逐项验证与 alpha2 兼容，无需改动。

## 迁移步骤

1. **前置（人类执行，本插件目录外）**：按「更新 DSH 源码 checkout」SOP 把 `~/.dsh/source/current` 升到 alpha2：`git pull --ff-only` → `pnpm install --prefer-offline` → `pnpm run build`（≥600s 前台），并同步 dev clone `D:/Projects/deepseek-harness/dsh`。插件类型面（tsconfig paths + Junction）与 vitest alias 都指向该树，完成后自动切换到 alpha2。
2. **唯一代码改动 — `src/settings.ts`**（最小 diff）：
   ```ts
   // 第 21 行：值导入改纯类型导入（settingsNamespace 已被 alpha2 删除）
   - import { settingsNamespace, type SettingsScope } from '@deepseek-ai/dsh-settings'
   + import type { SettingsScope } from '@deepseek-ai/dsh-settings'

   // 第 25 行：brand 工厂改裸字符串常量（alpha2 register/update 直接接受
   // 满足小写连字符约束的泛型字符串，无需品牌包装）
   - export const SETTINGS_NAMESPACE = settingsNamespace('interpreters')
   + export const SETTINGS_NAMESPACE = 'interpreters' as const
   ```
   其余 host 侧文件（config.ts / gateway.ts / tools.ts / runner.ts / index.ts）**无需改动**：`register('interpreters', Config, { base: entry as never })`、`scope.watch(...)`、`settings.update(SETTINGS_NAMESPACE, patch)` 在 alpha2 签名下原样编译。
3. **client 侧无需改动**：`connection/reset` 订阅、`ctx.locale.register/subscribe`、`settings.plugin.item` 槽位、`IconChevronDownOutline14`、`createSnapshotStore`、`CLIENT_EXTERNALS` 全部与 alpha2 一致（见对照表）。
4. **重建 lib/ 并过三件套**（本插件目录，约束内允许的本地构建）：
   ```powershell
   Push-Location D:/Projects/deepseek-harness/dsh-interpreters
   pnpm run typecheck   # 此时对 alpha2 .d.ts 编译，是 settingsNamespace 缺失的最早暴露点
   pnpm test            # vitest run（alias 指向 source/current 的 store src，alpha2 未改动）
   pnpm run build       # tsc build + esbuild client bundle + tsc types
   Pop-Location
   ```
   预期 typecheck 报错形态（改动前）：`Module '"@deepseek-ai/dsh-settings"' has no exported member 'settingsNamespace'`（TS2305）——改后消失。产物仍应含 `lib/index.js`、`lib/client.js`（`window.__ModuleLoader__.load({ id: '@huanlin/dsh-plugin-interpreters', ... })` 包裹）、`lib/types/`。
5. **profile 端生效**：本插件在 profile `web` 以 `link:D:/Projects/deepseek-harness/dsh-interpreters` 引用（若如此安装），重建 `lib/` 后 `~/.dsh/profiles/web/node_modules/@huanlin/dsh-plugin-interpreters/lib/` 直接可见，**无需 `dsh plugin add/update` 重装**。对外发布走 huanlinoto 发布 SOP（预构建策略：build → `git add lib/ && commit && push`；npm 分发另走 `pnpm publish`）。建议本次提交版本号 bump 至 `0.3.1`（适配性 patch），可选同步把 peer 范围提到 `^0.1.2-alpha.2`。
6. **重启验证**：由人类重启 `dsh web` 进程 + 浏览器硬刷新（`Ctrl+Shift+R`）后进入下节验证。
